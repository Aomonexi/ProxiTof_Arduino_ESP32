**Date**: January 31, 2026

## Quick Answer

**Q: Where does the ML model go?**  
**A**: The model is **built into the firmware**, NOT stored on the SD card.

**Q: Can I collect data without a model?**  
**A**: YES! Manual flagging works without ML. Just press ACTION in Dashboard mode.

**Q: Is TensorFlow Lite considered AI?**  
**A**: YES! It's a neural network for pattern recognition (machine learning/AI).

## Model Deployment Process

### Step 1: Collect Training Data (No Model Needed!)

**What You Do:**
1. Build and flash firmware (works without ML model)
2. Set detection mode to "Algorithm" (Mode 1)
3. Ride bike normally
4. Press ACTION button in Dashboard when near-miss occurs
5. System logs data with `flag_manual=1`

**What Gets Logged:**
```csv
timestamp_ms,flag_manual,flag_auto,tof_00,tof_01,...,roll,pitch,yaw,accel_x,...
1234567,1,0,450,523,612,701,...,12.3,-5.7,180.0,0.98,...
```

**Where Data Goes:**
- SD card: `/sdcard/data_YYYYMMDD_HHMMSS.csv`
- Each button press creates a row with `flag_manual=1`
- Safe examples have `flag_manual=0`

**How Much Data:**
- Minimum: 100 near-miss + 1000 safe examples
- Recommended: 200 near-miss + 2000 safe examples
- More data = better model

---

### Step 2: Train Model on PC

**What You Do:**
1. Remove SD card from device
2. Copy CSV files to `data/raw/` folder on PC
3. Run training script:
   ```bash
   python tools/quick_start_ml.py
   ```

**What Happens:**
1. **Load Data** - Reads all CSV files
2. **Prepare Features** - Extracts 25 features (16 ToF + 9 IMU)
3. **Normalize** - Calculates mean and std for each feature
4. **Train Model** - TensorFlow creates neural network
5. **Convert to TFLite** - Optimizes for ESP32
6. **Generate C Code** - Creates `model_data.h` file

**Output Files:**
```
components/ml_inference/include/model_data.h  ← Model embedded here!
models/near_miss_model.tflite                 ← TFLite model (for reference)
models/scaler.pkl                             ← Normalization parameters
models/training_history.png                   ← Training graph
```

**What's in model_data.h:**
```c
// Auto-generated by quick_start_ml.py
// DO NOT EDIT MANUALLY

// Model size: 2456 bytes
const unsigned char g_model_data[] = {
    0x1c, 0x00, 0x00, 0x00, 0x54, 0x46, 0x4c, 0x33,
    // ... 2456 bytes of model weights ...
};
const int g_model_data_len = 2456;

// Scaler parameters (mean and std for normalization)
const float scaler_mean[25] = {
    // ToF features (16)
    523.4, 567.2, 612.8, ...,
    // IMU features (9)
    0.5, -2.3, 45.6, ...
};

const float scaler_std[25] = {
    // ToF features (16)
    156.7, 189.3, 201.5, ...,
    // IMU features (9)
    8.9, 12.4, 67.8, ...
};
```

**Training Time:**
- Small dataset (1000 samples): ~2 minutes
- Medium dataset (5000 samples): ~5 minutes
- Large dataset (10000 samples): ~10 minutes

### Step 3: Rebuild Firmware with Model

**What You Do:**
```bash
idf.py build flash monitor
```

**What Happens:**
1. **Compile** - Includes `model_data.h` in firmware
2. **Link** - Model embedded in flash memory (~2.4KB)
3. **Flash** - Uploads firmware to ESP32
4. **Boot** - ML inference initializes with model

**Expected Serial Output:**

### Step 4: Use ML Detection

**What You Do:**
1. Navigate to Near-Miss mode (Mode 5)
2. Set detection mode to "Hybrid" (Mode 0) or "Neural Net" (Mode 2)
3. Ride bike normally
4. System automatically detects near-misses using ML

**What Happens:**
1. **Read Sensors** - ToF and IMU data (60 Hz)
2. **Normalize Features** - Apply scaler parameters
3. **ML Inference** - Neural network predicts probability
4. **Threshold** - If probability > 70%, flag as near-miss
5. **Log Event** - Save with `flag_auto=1`

**Inference Performance:**
- Without ESP-NN: 50-100ms (too slow for 60 Hz)
- With ESP-NN: 10-15ms (perfect for 60 Hz!)
- Frame time: 16.67ms (60 Hz)
- Remaining: 1-6ms for other tasks

## Why Model is Built Into Firmware

### Advantages ✅

1. **Fast Access** - Model in flash memory (no SD card delays)
2. **Reliable** - No file corruption or missing file issues
3. **Secure** - Model protected in firmware
4. **Simple** - No file management needed
5. **Efficient** - Direct memory access

### Disadvantages ❌

1. **Requires Rebuild** - Must recompile to update model
2. **Flash Space** - Uses ~2.4KB flash memory
3. **No Runtime Update** - Can't swap models without reflashing

### Why Not SD Card?

**SD Card Approach (NOT USED):**
- ❌ Slower access (file I/O overhead)
- ❌ File corruption risk
- ❌ Missing file errors
- ❌ More complex code
- ❌ SD card must be present

**Firmware Approach (USED):**
- ✅ Fast access (direct memory)
- ✅ No file errors
- ✅ Always available
- ✅ Simple code
- ✅ Works without SD card

## TensorFlow Lite = AI?

### Yes, It's AI!

**What is TensorFlow Lite?**
- Machine learning framework
- Optimized for embedded devices
- Runs neural networks
- Pattern recognition
- Supervised learning

**What is a Neural Network?**
- Artificial intelligence algorithm
- Learns from examples (your button presses)
- Finds patterns in data
- Makes predictions
- Adapts to your riding style

**How It Learns:**
1. **Training Data** - Your flagged near-misses
2. **Feature Extraction** - 25 sensor values
3. **Pattern Recognition** - Finds correlations
4. **Weight Optimization** - Adjusts neural connections
5. **Validation** - Tests on unseen data
6. **Deployment** - Embedded in firmware

**What It Predicts:**
- Input: 25 normalized features (ToF + IMU)
- Output: Probability of near-miss (0.0 to 1.0)
- Threshold: 70% = near-miss detected

**Example:**
```
Input Features:
- ToF distances: [450, 523, 612, 701, ...]
- IMU data: [roll=12.3, pitch=-5.7, yaw=180.0, ...]

Neural Network Processing:
- Layer 1: 25 inputs → 16 neurons (ReLU)
- Layer 2: 16 neurons → 8 neurons (ReLU)
- Layer 3: 8 neurons → 1 output (Sigmoid)

Output:
- Probability: 0.853 (85.3%)
- Decision: YES (> 70% threshold)
- Result: flag_auto = 1
```

## Common Questions

### Q: Do I need a model to start?
**A**: No! Manual flagging works without ML. Collect data first, train later.

### Q: Where does the model go?
**A**: Built into firmware (`model_data.h`), NOT on SD card.

### Q: How do I update the model?
**A**: Train new model, rebuild firmware, flash to ESP32.

### Q: Can I use multiple models?
**A**: Not currently. Only one model embedded at a time.

### Q: What if I don't have enough data?
**A**: Start with algorithm mode, collect more data, train later.

### Q: How accurate is the model?
**A**: Depends on training data quality. Aim for 90%+ accuracy.

### Q: Can the model learn while running?
**A**: No. Training happens on PC, then model is deployed.

### Q: What if the model is wrong?
**A**: Collect more diverse data, retrain, redeploy.
