## Overview

The ProxiTof system uses TensorFlow Lite Micro for real-time near-miss detection on the ESP32-S3. The ML pipeline includes data collection, model training on PC, and deployment to the device.

### Key Points
- **Model Location**: Built into firmware (`model_data.h`), NOT on SD card
- **Features**: 25 total (16 ToF + 9 IMU)
- **Ground Truth**: `flag_manual` (button press), NOT `flag_auto`
- **Inference Time**: 10-15ms with ESP-NN acceleration
- **Model Size**: ~2.4KB (450 parameters)

## Quick Start

### Phase 1: Data Collection (No Model Needed)
```bash
# Build and flash firmware
idf.py build flash monitor

# On device:
# 1. Set detection mode to "Algorithm" (Mode 1)
# 2. Ride bike, press ACTION to flag near-misses
# 3. Collect 100+ near-miss, 1000+ safe examples
```

### Phase 2: Model Training (On PC)
```bash
# Copy CSV files from SD card to data/raw/
# Run training script
python tools/quick_start_ml.py

# Output: model_data.h with trained model
```

### Phase 3: Model Deployment
```bash
# Rebuild firmware with new model
idf.py build flash monitor

# Verify ML is active in serial output
```

### Phase 4: Production Use
- Set detection mode to "Hybrid" (Mode 0)
- System uses both algorithm and ML for detection

## Detection Modes

| Mode | Name | Description |
|------|------|-------------|
| 0 | Hybrid | Algorithm + ML (best accuracy) |
| 1 | Algorithm | Rule-based only (for data collection) |
| 2 | Neural Network | ML only (experimental) |

### Switching Modes
1. Navigate to Near-Miss mode (Mode 5)
2. Press ACTION button to cycle modes
3. Mode persists across power cycles

## Feature Engineering

### 25 Input Features

**ToF Sensor (16 features)** - 4×4 distance grid:
```
tof_0_0, tof_0_1, tof_0_2, tof_0_3
tof_1_0, tof_1_1, tof_1_2, tof_1_3
tof_2_0, tof_2_1, tof_2_2, tof_2_3
tof_3_0, tof_3_1, tof_3_2, tof_3_3
```

**IMU Sensor (9 features)**:
- `accel_x`, `accel_y`, `accel_z` - Acceleration
- `gyro_x`, `gyro_y`, `gyro_z` - Angular velocity
- `roll`, `pitch`, `yaw` - Orientation

### Feature Normalization
Features are normalized using StandardScaler (mean=0, std=1):
```c
// In model_data.h (auto-generated by training)
static const float scaler_mean[25] = {...};
static const float scaler_std[25] = {...};
```

## Model Architecture

```
Input Layer (25 features)
    ↓
Dense Layer (16 neurons, ReLU)
    ↓
Output Layer (2 neurons, Softmax)
    ↓
Prediction: [P(safe), P(near_miss)]
```

**Parameters**: ~450 total
- Input→Hidden: 25×16 + 16 = 416
- Hidden→Output: 16×2 + 2 = 34


## Data Collection Best Practices

### Ground Truth Labeling
- **flag_manual**: Set by button press (use for training)
- **flag_auto**: Set by algorithm/ML (do NOT use for training)

### Collection Strategy
1. Use Algorithm mode (Mode 1) during collection
2. Press ACTION button when near-miss occurs
3. LED flashes blue to confirm
4. Collect diverse scenarios:
   - Different speeds
   - Different distances
   - Different vehicle types
   - Different road conditions

### Recommended Data Volume
- **Minimum**: 100 near-miss, 1000 safe examples
- **Recommended**: 500+ near-miss, 5000+ safe examples
- **Class balance**: ~10:1 ratio (safe:near-miss)

## ESP-NN Optimization

The system uses ESP-NN for hardware-accelerated inference:

### Performance Settings (sdkconfig.defaults)
```
CONFIG_ESP_DEFAULT_CPU_FREQ_MHZ_240=y
CONFIG_ESPTOOLPY_FLASHFREQ_80M=y
CONFIG_ESPTOOLPY_FLASHMODE_QIO=y
CONFIG_ESP_NN_OPTIMIZATIONS=y
```

### Memory Optimization
- Tensor arena: 8KB (16-byte aligned)
- Model size: ~2.4KB
- Total ML RAM: ~12KB

### Inference Timing
- Without ESP-NN: 50-100ms
- With ESP-NN: 10-15ms (5-10× faster)

## Troubleshooting

### "No trained model available"
**Cause**: Model not yet trained or `model_data.h` has placeholder  
**Solution**: Train model with `python tools/quick_start_ml.py`

### "ML inference failed"
**Cause**: Model incompatible or memory issue  
**Solution**: Check model architecture matches expected input (25 features)

### Low Accuracy
**Causes**:
- Insufficient training data
- Class imbalance
- Feature mismatch

**Solutions**:
- Collect more data
- Use class weighting in training
- Verify CSV column names match expected features

### Build Errors
```bash
# Missing dependencies
idf.py reconfigure  # Downloads TFLite Micro

# Clean build
idf.py fullclean
idf.py build
```
